# Detailed frontend-design workflow

Apply relevant sections for substantial design decisions, not every edit. Make interfaces specific to audience/content/task and preserve incumbent identity during refinement. Editorial composition and softer forms are suitable choices, not universal requirements.

## Establish a direction

Inspect content, components, primary flow and devices. Separate facts/fixtures; never invent customers, awards, testimonials, metrics or licenses. Write audience, task, priority, character, constraints and observable acceptance. Narrow corrections need focused comparisons, not presentation ceremonies.

For substantial composition, compare genuinely different hierarchy/navigation using representative content and [composition](composition.md). Palettes alone are not directions. Choose within authority and explain consequences without invented approval stops. Translate reference mechanics without copying identity/assets.

Build a representative vertical slice before multiplying sections: primary view, detail/action and real state at desktop/narrow widths. A polished hero does not make a coherent journey.

## One coherent system

Use [humanizer](../../humanizer/SKILL.md) for wording. Remove promotional/title layers lacking orientation while retaining meaningful headings/navigation/accessibility. Establish dominance through placement, scale, grouping and contrast with actual long titles/metadata.

Record useful direction constraints in existing docs or concise DESIGN.md: type/fallback, spacing/width, surfaces, radii, media, states and responsive decisions. Reuse components/tokens before dependencies/layers. Use [interface craft](interface-craft.md). Open reading areas can coexist with rounded controls/media; blur/gradients/radii cannot repair hierarchy.

Parallel slices need owner and shared composition, fixtures, tokens, component/state/responsive contracts. Inspect the integrated page; polished sections can compete. Each hero/card/testimonial/CTA needs truthful content and journey purpose. Familiar patterns are valid when useful.

## Real behavior

Use [journey continuity](journey-continuity.md) across views/dialogs/editors. Check orientation, ownership and work preservation through round trips, not isolated captures.

Use semantic controls, meaningful reading order, focus, connected labels/errors and keyboard/pointer actions. Check applicable contrast, reflow, targets and motion standards. Screenshots cannot prove interaction accessibility.

Design encountered loading/empty/failure/partial/success/disabled/destructive states. Put recovery near failure and preserve input. Distinguish absent items, filter misses and load failure; static pages need no invented transactional states.

Responsiveness changes priorities/relationships, not scale alone. Check actions, long text, missing media, realistic density, intermediate widths and relevant zoom. Preserve reduced motion/static behavior.

Render from authoritative state rather than synchronized flags/counts. Apply functional extraction when its criteria warrant; adapters own requests/navigation/effects. Preserve actual optimistic-update, cancel/retry/undo contracts; attractive feedback cannot invent completion.

## Observe and iterate

Use [rendered review](rendered-review.md) for substantial builds/audits. Inspect running primary/detail/state/narrow layouts, primary action, keyboard and recovery. Probe stale selection, permissions, unknown outcomes and partial success where relevant. Record viewport, identity, fixtures and observations.

Critique purpose/hierarchy, order/density, alignment/rhythm, action/state, type/media, then surfaces. Findings need visible defect, consequence and smallest correction. “Generic” alone is not evidence; cards can flatten editorial priority or correctly enable comparison.

Batch material fixes, repeat comparable captures/actions and preserve behavior. Use authorized independent review when available. Record defect→hypothesis→observation→verdict. Stop at observed acceptance without material findings; disclose tradeoffs and retain successful patterns.

Deliver brief/direction, working artifact/bounded critique, applicable shared contract, rendered/interaction evidence and gaps. Missing tools leave verification incomplete; source review cannot certify visuals. Avoid cosmetic cycling or promises of authenticity from aesthetic labels.
