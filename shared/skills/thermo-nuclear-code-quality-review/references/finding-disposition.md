# Finding disposition and counterevidence

Load when findings are disputed, several audits overlap, or a revision claims to resolve an ownership concern. Calibrate the judgment to demonstrated structure and the reviewed artifact. This is not a separate verdict vocabulary.

## Identify the mechanism before debating the remedy

Separate an observed defect, a structural maintenance concern and a missing fact. “Three files” is an observation, not a mechanism. “The cancellation rule is independently maintained in three owners, and one permits a retry the others prohibit” identifies the policy and consequence.

A correctness fix can close the immediate mismatch while leaving the duplicated rule. Conversely, a coherent ownership change can be structurally useful before a broader performance claim is measured. State which concern is being resolved; do not treat passing tests as proof of every property.

Keep findings proportional to the reviewed scope. Include an older concern when the change depends on or worsens it. Do not create criticism quotas, demand unrelated modernization or turn an uncertain external consumer into a demonstrated defect.

## Counterevidence should change the verdict

Inspect evidence that a small wrapper owns transaction lifetime, access enforcement, initialization or a supported public contract. If that responsibility is real and coherent, the wrapper may earn its place. Withdraw an unsupported removal recommendation rather than moving the goalposts.

For a proposed pure transition, verify whether consumers actually use its policy. Pure code can still duplicate knowledge or expose mutable nested aliases. Functional style supports the review; it is not a substitute for traced ownership and preservation.

For a file split, inspect the resulting import graph, state identity and failure owner. A compliant 500-line count remains mandatory but does not close a distributed-policy finding. An oversized file in reviewed scope still prevents acceptance without exception; missing edit authority is a coordination issue, not a passing verdict.

## Worked case: overlapping cancellation findings

A security audit notices that a cancelled job can still perform a prohibited write. A maintainability review notices two cancellation predicates with incompatible meaning. They may share one root cause but require different evidence: denied effects for security, authoritative policy and migrated consumers for structure.

Merge the repair plan around the shared cause without collapsing the acceptance criteria. Compare a narrow authoritative predicate with a broader state model. Prefer the smallest remedy that accounts for current callers, partial failure and retry; do not introduce an event framework just because cancellation involves state.

If only the UI switches to the new rule while the worker retains its predicate, the structural concern remains. If all relevant callers migrate but real boundary enforcement is untested, structural inspection can support its own scoped conclusion while the security claim stays unverified.

## Re-review changed evidence

Inspect the current artifact, relevant callers and removed owners. Check whether the proposed remedy eliminated the original mechanism, merely renamed it or introduced a nearby cost such as a mutable singleton. Use the original preservation constraints and add checks only for consequences actually created by the revision.

Findings can be resolved, retained with a concrete reason or remain unanswered in the report, but the final skill verdict remains exactly one of meets the bar, needs restructuring or insufficient evidence. An accepted tradeoff is not a license to ignore a material unresolved structural problem or the hard size gate.

Do not repeatedly report a resolved finding from an old diff. Record what changed the judgment and the bounded evidence. Separate independent worker checks from integrated seam inspection; neither silently substitutes for the other.

## Useful final evidence

Show the rule's current owner, migrated consumers, removed mechanism and preservation observations for material repairs. State unavailable context that would settle an unresolved decision. A concise supported clean result is valid.

No claim of universal security, correctness or maintainability follows from a source verdict. Treat observed runtime checks as specific evidence, and source reasoning as source reasoning. The coordinator owns final disposition across the complete authorized task.
