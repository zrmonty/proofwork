# Audit-stack specification

The entry is thin orchestration, not another copy of its constituent audits. It selects lenses through the coordinator, owns one scope/identity, finding ledger, dependency order and integrated result. Lens skills own reachability, security, duplication, performance, coverage, architecture and structural proof obligations.

Acceptance: preserve report-only authority; do not recursively redispatch or create a scheduler; merge common causes while retaining independent obligations; avoid overlapping modifying owners; recheck evidence invalidated by integration; return assessed/not-applicable/unverified statuses and remaining actions. Conditional language, UI, release and delivery work must follow actual scope.

references/repair-interactions.md owns cross-lens conflicts. A shared export-cache defect receives one repair with security isolation, representation and measurement obligations. Deadness precedes extraction; later changes reopen affected observations. Missing tools, metrics or live-host evidence remain gaps. Routing/build checks are distinct from an observed application audit.
