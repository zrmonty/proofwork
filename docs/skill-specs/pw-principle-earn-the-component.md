# Specification: pw-principle-earn-the-component

Citable principle: `earn-the-component`. Trigger: Use before adding a service, layer or dependency.

Decision contract: Name the current requirement its boundary serves. Compare an existing or simpler mechanism, including operational ownership; hypothetical future reuse does not earn a component.

Acceptance evidence: Record the selecting requirement and observable condition that would reopen the decision.

Apply only to the actual assignment. The principle adds a decision lens, not a second workflow or authorization. Packaging validation establishes discoverability, not agent compliance.
