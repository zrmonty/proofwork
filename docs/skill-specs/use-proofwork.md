# Specification: use-proofwork

Purpose: one entry point selects the engineering method and owns a verified team result, including goal continuation.

Inputs: authorized task, repository instructions, design, affected files, native goal status, capabilities, checkpoints and supplied limits.

Workflow: discover host; execute the packaged pure router; read returned assets; establish criteria; initialize/recover run; assign bounded ownership; integrate; review; verify; checkpoint; deliver within authorization.

Output/evidence: integrated artifact/report, actual criterion evidence, finding disposition, checkpoint and accurate host lifecycle result. Commit delivery loads commit-features and validates the actual range.

Boundaries: no implicit goal creation, replacement scheduler, cross-provider claims, outside-owner writes or unrequested external publication. Defaults never override user/host/project requirements.

Behavioral acceptance: pressure cases 1, 2 and 5 in evals/orchestration-pressure.md; route runs automatically; existing goal objective is preserved; stale evidence and unsettled workers cannot establish completion. Unavailable host capabilities remain unverified.

Original authorship: authored from Proofwork's requirements. Installed pstack was development guidance only; no source skill content is imported. Baseline record: evals/results/baseline.txt, fresh Codex CLI execution by coordinator before authoring. Native safeguards already passed; missing product-specific checkpoints/contracts and routing are the concrete additions. Post-skill execution is recorded separately by coordinator.
