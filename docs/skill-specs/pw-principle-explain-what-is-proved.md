# Specification: pw-principle-explain-what-is-proved

Citable principle: `explain-what-is-proved`. Trigger: Use when reporting a result or accepting completion.

Decision contract: Match each claim to its observation and current artifact. Separate executed checks, operator assertions and unknowns; test counts cannot stand in for coverage or correctness.

Acceptance evidence: State the proved outcome, meaningful checks and specific unverified criteria.

Apply only to the actual assignment. The principle adds a decision lens, not a second workflow or authorization. Packaging validation establishes discoverability, not agent compliance.
