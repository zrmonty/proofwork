# Does Proofwork reduce the engineering burden?

This is a measurement protocol, not a claim of superiority. Compare bare host use with Proofwork on the same brief, checkout, model settings, authority and machine. Newcomers describe outcomes without technique names. Compare optional model configurations separately so instruction and model changes are not confounded.

## Paired procedure

Freeze acceptance and preservation checks before dispatch. The harness has nine executable tasks, including production configuration isolation. Use fresh isolated sessions and verify the bare condition loads no automatic engineering plugin. Alternate condition order per task/repetition pair. Start with one bounded pair; expand to three repetitions across representative tasks only after a usable pilot. Permission/tool failures are separate from delivered defects.

Freeze a realistic correction and its expected preservation before the trial. Observe it after the first reviewable slice. The batch runner is single-turn; correction behavior requires a reviewed multi-turn runner or participant session. Do not claim batch fixtures exercise corrections automatically.

## Observation contract

Save a local array keyed by task, arm and repetition. Grade traces and artifacts, with blinded independent review where practical. Collect participant feedback with consent. Missing observations remain unknown.

The aggregator reports paired denominators and Proofwork-minus-bare deltas; duplicate identities are rejected. Records are observer-reported, not authenticated human approvals. Missing observations, incomplete runners and unmatched tasks stay visible. Zero requires an actual check. Runner duration is not time to a verified slice.

## Publication and decisions

Publish reviewed sanitized aggregates, fixture/source/host/model identities, ordering, settings, unusable rows, measured outcomes and limits. Show a public-safe before/after diff with rerun checks and residual operating work. Raw prompts, traces, private systems, identities and credentials remain local. Attribution and customer-system descriptions require consent.

Report defect/rework rates with numerator, denominator and observation window. Do not turn tiny samples into rankings or regulated-system certification. Explain differences in authority and tooling. A repair example proves that example, not comparative quality. Change one observed friction point and repeat comparable cases.

The public-release comparison gate remains unmet until usable agent runs exist. Recruitment and ship feedback require actual volunteers; templates are not participants.

Set comparisonValid to true on each observation only after checking authority, host/plugin isolation and trace integrity. The report separates successful runner exits, accepted fixture pairs and reviewer-approved comparable pairs. Exit zero alone never makes user-effort metrics eligible.
