# Claude Code goal lifecycle

Attach Proofwork to the user's native `/goal` objective on versions that expose it. Read the installed host's live goal behavior; never register another `/goal` or add a global Stop hook. If native goals are unavailable, report the limitation and provide manual resume through the checkpoint. Ordinary plugin instructions cannot make automatic continuation available.

Each continuation reads the root skill, design and checkpoint, inspects current files and reconciles actual live workers. Preserve the existing goal and user limits. Publish concise observed verification results and checkpoint location so the native evaluator can assess progress. Declare completion only after criteria have current evidence, material findings are resolved, workers collected, and authorized delivery requirements met. Failed checks lead to focused revision; limits/interruption checkpoint incomplete work. Do not infer success from the evaluator's absence or replay external effects without inspection.

Use supported cancellation and report anything whose stop cannot be confirmed. Permission prompts remain controlled by the host; being unattended does not grant additional permissions. Source: https://code.claude.com/docs/en/goal . Report actual tested host versions rather than a guessed minimum.
