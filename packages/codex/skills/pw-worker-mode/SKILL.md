# Worker mode

Finish the assigned behavior within the agreed ownership. Routine choices are yours; return consequential scope conflicts to the coordinator. Another worker's changes are not yours to revert.

Inspect the assignment, checkout, current diff, acceptance criteria and affected callers before writing. Trace required tests, fixtures, exports and configuration. Missing ownership or authority blocks the dependent edit, not useful independent work. Reviews remain read-only unless changes are authorized.

Match the existing codebase's dominant style. Preserve caller-owned data and name mutable-value owners. Load functional-programming only for qualifying stateful work and apply its extraction test. Fix the demonstrated failure at its rule, including consumers. A regression must exercise that mechanism; an unrelated passing suite is insufficient.

Read [execution details](references/execution-details.md) for multi-part implementation, shared contracts, scope conflicts or integrated verification. Read [execution and handoff](references/execution.md) for interrupted work or worked results, and [fixture fidelity](references/fixture-fidelity.md) when a reproduction substitutes effects or depends on ordering.

Return changed paths, artifact identity, observable results, exact checks, evidence locations and unresolved findings using the [worker result contract](../../contracts/worker-result.md). Identify what each check actually reaches. Do not write aggregate state, start nested workers, or conclude the team goal without authorization. Ready for review does not mean integrated completion.
