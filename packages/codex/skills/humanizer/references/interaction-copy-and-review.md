# Interaction copy and review

Use when wording participates in actions, states, accessibility or localization. The observed event is authoritative; copy cannot strengthen its promise.

## Match the state

| State | Copy obligation | Required observation |
| --- | --- | --- |
| Initially empty | Explain content and real first action | Request succeeded, list empty |
| Filtered empty | Explain filter, offer supported reset | Existing records may be hidden |
| Failed load | Name unavailable content, safe recovery | No data loaded does not mean no data exists |
| Failed save | Explain outcome and retained work | Server result known; repeat safe |
| Uncertain payment | Explain uncertainty, safe lookup | Reconcile before encouraging another charge |
| Success | Confirm actual effect | Queued is not completed |
| Destruction | Name object, scope, reversibility | Undo/retention/permissions truthful |

Examples, conditional on actual behavior:

```text
No events yet. Create an event to invite your group.
No events match these dates. Clear the date filter.
We couldn't load events. Try again.
Your export is queued. We'll show the download here when it's ready.
Delete these 3 drafts? This can't be undone.
```

The export requires updates at that location; the deletion requires unavailable recovery. Adapt copy or expose the missing behavior question. Do not add behavior incidentally to make wording true.

## Actions and accessible context

Use verb/object for the consequence: Save draft, Send invitation, Download report. “Continue” can suit a clear intermediate step; it conceals immediate purchase/publication/deletion. Keep visible labels, accessible names and confirmations aligned. Icon-only controls need meaningful accessible names; shortening must not lose the object or confuse adjacent actions.

Form guidance should explain actual format, privacy or consequences before submission. Place field errors with their controls and retain useful general errors for non-field failures. Avoid redundant “Please enter” filler. Describe correction without blame: “Choose a date after today.” Admit unknown causes instead of inventing reassurance.

## Truth and privacy across surfaces

Inspect readers and placement. Do not expose tokens, private identifiers, raw queries or another person's details through friendlier errors. Use incumbent public errors/support references. Preserve account/resource disclosure policy; generic access responses must not become existence leaks.

Compare button, confirmation, toast, detail view and notification against authoritative state. Dispatch may establish “Invitation sent”; joining requires another event. A short toast cannot imply more than the detailed status. Report missing state contracts rather than quietly changing behavior.

## String contracts

Preserve localization IDs, named variables, plurals, escaping, markup boundaries and formatter ownership. Translate whole messages, not fragments assuming English order. Use locale-aware dates/numbers/currency. Check realistic long names, zero/one/many counts and available pseudolocalization/previews. Do not assume English length, tone or ordering generalizes; unavailable language review stays explicit.

Approved legal/regulated text has a meaning contract. Produce a concrete proposed revision where authorized; material promises/consent clauses need designated review. Friendliness must not bury consequences.

## Bounded review

Compare old/new flow with facts and actual effects. Removed headings/paragraphs must contain no unique required information; preserve orientation and semantic structure. Read ordinary/failure states together for stable vocabulary and excessive repetition.

Inspect implemented copy at representative widths, long labels and errors; check affected accessible names/localization with available tools. Exercise changed states/actions when wording depends on them. Reuse meaningful existing checks; avoid brittle style-only tests.

For text proposals, identify assumptions and missing render/interaction checks. For implementations, report checked surfaces and source identity. A natural sentence does not prove a functional flow; a screenshot does not prove keyboard behavior.
