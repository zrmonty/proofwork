# Choose the design work

Select the smallest approach that fulfills the outcome; combine approaches only when the task crosses them.

## Resolve scope from evidence

Inspect the surface and one source of its visual rules before editing: theme, tokens, component family or
existing page. For a screenshot-only brief, separate observable appearance from unknown behavior. Missing
project documents do not justify replacing a coherent interface. Reuse useful context rather than requiring
new onboarding files for every edit.

A narrow request has a named defect or property. A broad request can authorize stronger choices, but still
preserves audience, content truth and product behavior. If "make this better" leaves consequential scope
unclear, inspect first and state a bounded interpretation. Ask when preservation versus replacement would
spend substantial effort or discard a user-owned direction.

## Establish a new composition

Write a short working brief: visitor's task, primary content, constraints, emotional character and acceptance.
Then state a visual thesis with an observable mechanism. For a publication, a dominant essay and compact
archive can express editorial judgment. For a review queue, stable row geometry and conspicuous exceptions
can express confidence. Neither needs a generic marketing hero.

When the choice is consequential, sketch two genuinely different content structures against the same
representative material. Choose for comprehension, action and fit; color variants alone do not test structure.
Use explore-options only when uncertainty warrants its overhead. Implement the selected direction rather
than blending every candidate into an incoherent compromise.

Deliver a working primary view, its meaningful action/detail and encountered states. Record the few design
rules that should survive future work in the project's existing notes, or a concise DESIGN.md when useful.
Do not create a documentation system as a prerequisite to changing a button.

## Diagnose before correcting

For critique, connect an observation to a task consequence: equal emphasis hides the lead; unlabeled amounts
prevent comparison; a sticky action covers the focused field. State location, conditions and smallest remedy.
Distinguish functional/accessibility failures, hierarchy problems and optional taste. A coherent result can
pass without a quota of findings or a numerical beauty score.

For repair, fix the controlling cause before cosmetic symptoms. Simplifying navigation will not repair lost
drafts; increasing contrast will not repair ambiguous status ownership. Keep authority and verified facts
visible. A critique request does not authorize silently implementing its recommendations.

## Refine a successful direction

Identify the weak dimension and preserve the others. If a page feels flat, try stronger editorial priority,
image treatment or a distinctive type relationship before adding decorative sections. If it feels noisy,
reduce competing accents and unnecessary containment before stripping essential affordances.

Finish work aligns geometry, icon weight, wraps, focus, state transitions and responsive behavior. It does not
replace approved copy, palette or information architecture without a reason within scope.

## Consolidate established foundations

Trace repeated visual decisions and their consumers. Promote actual roles such as reading width, subdued
metadata, destructive action and selected row into existing tokens/components. Keep justified differences
between reading pages and dense tools. A shared radius does not imply shared interaction behavior.

Return the changed rule and consumers, preserve keyboard/state contracts and inspect representative uses.
Do not introduce a framework, theme service or component dependency merely to remove a few literals.
