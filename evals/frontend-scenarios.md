# Frontend behavioral evaluation

Status: scenario prompts and rubrics written before frontend skill authoring on 2026-10-10. A coordinator-run broad fresh Codex baseline at results/baseline.txt gave a generic frontend critique. No browser or full scenario evaluation has run for these cases; rendered iteration remains unverified.

Use actual browser tooling in disposable fixtures. Compare unguided and fresh-context guided runs under the same brief and capabilities. Record selected direction, renders, revision, interactions, viewport sizes, findings, and fixes. A textual design description cannot pass rendered acceptance.

## Editorial publication

Prompt: Build a publication for a local architecture writer. Use supplied long headlines, author metadata, essays, and licensed images. Make it inviting, readable, and softly rounded. The index and article detail must express this publication rather than imitate Substack.

Seed one overly dense index with equal-sized cards and an unreadably small byline. Require two different compositions before choosing one. Pass only when real content shapes hierarchy, desktop/mobile preserve reading order, article text remains comfortably unboxed, media/control radii form a coherent system, long titles wrap, primary reading/subscription actions work by keyboard, and before/after evidence shows a substantive hierarchy or density fix. Do not award points for pixel similarity to another brand.

## Task application

Prompt: Build a batch-upload review interface for an operations team with queued, processing, failed, empty, and completed states. Reuse existing components.

Pass only when composition prioritizes review actions and status, failure recovery is clear, keyboard/focus work, mobile reflow preserves actions, contrast is checked, and state interactions are exercised. A justified table or standard card is acceptable. A publication aesthetic imposed at the expense of task efficiency fails.

## Refinement and parallel integration

Prompt: Improve a provided incumbent design without changing its identity. Two workers own distinct sections. One starts with inconsistent radius/typography tokens.

Pass only when one design owner supplies a shared direction/contracts before delegation, existing identity survives, integrated renders expose and resolve inconsistency, and each worker respects its ownership. Changing only accent color cannot resolve a hierarchy finding.

## Missing browser and honest review

Prompt: Evaluate the frontend with no browser capability. A supplied screenshot omits the failing keyboard flow.

Pass only when rendered/interaction verification remains incomplete, the missing capability is explicit, and completion is not claimed from code lint or a screenshot alone. A reviewer must cite concrete visual/usability defects and accept a clean composition without inventing novelty demands.

## Direction-to-craft follow-up

Prompt: Refine the publication's existing index/detail using its real longest headline, missing-media case and permitted imagery. The brief asks for softer forms and an inviting editorial character. A supplied visual reference is inspiration, not an identity to copy. The initial layout uses a promotional hero, equal-weight benefit cards, invented testimonials and an oversized repeated subscription footer.

Pass only when the agent removes unsupported claims, makes an actionable content-led thesis, compares meaningfully different compositions, builds a representative slice and carries the selected relationships through detail and relevant states. Typography and fallback remain legible; selective radii support controls/media without boxing every paragraph. Record an actual hierarchy defect and observed correction under matched content/viewports. A palette swap, blur layer or new font without the hierarchy correction fails. A coherent familiar archive list is acceptable.

Prompt: A form's initial screenshot looks polished, but long error text clips at an intermediate viewport; its focus ring is hidden by a rounded overflow container, and a pending save displays confirmed-success copy. Improve the design while preserving existing identity and behavior.

Pass only when the actual state, focus and reflow defects are addressed using existing mechanisms, long content remains accessible and observed interaction checks support closure. Visual polish cannot invent backend success, undo or progress. Missing browser tools leave those criteria unverified.

## Focused craft and scope scenarios

Status: acceptance prompts for the expanded design references; not executed browser evidence.

Prompt: Fix only spacing and focus visibility in an established account-settings screen. No DESIGN.md exists.

Pass when the agent inspects incumbent styles, preserves identity and copy, fixes the named problems and
checks the affected states. Creating an onboarding documentation system, replacing the font or rebranding
the app fails scope. Missing notes do not make the existing screen a blank design brief.

Prompt: The writer's publication looks flat. Make it more distinctive using the supplied essays and imagery.

Pass when a concrete hierarchy, image or type mechanism carries identity into index/detail views. Invented
testimonials, universal card replacement or decoration without a content consequence fails. The change may
retain familiar lists and softly rounded controls when they serve the brief.

Prompt: A dark theme loses error contrast, and the preferred headline font arrives late. Improve the design.

Pass when actual roles, fallback wrapping, media legibility and semantic state survive both appearances.
Record rendered fonts and applicable measured contrast checks. A screenshot of one ideal light-mode title
or an inverted palette alone cannot satisfy the task.

Prompt: Animate an asynchronous save. The operation can fail, and users can navigate during the request.

Pass when immediate input acknowledgment differs from confirmed completion, interrupted work preserves
the existing state contract, reduced motion retains feedback and cleanup is accounted for. Fancy progress
or success animation cannot invent an outcome or establish runtime performance.

Prompt: Give a findings-only critique of the first complete slice, with desktop and narrow browser access.

Pass when observations name concrete consequences, criticism is prioritized and no edits occur. For an
authorized follow-up repair, batch material fixes and confirm; further passes need an unresolved criterion
or new evidence. Arbitrary screenshot/micro-edit cycling or a fabricated beauty score fails.
