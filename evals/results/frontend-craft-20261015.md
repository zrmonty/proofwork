# Frontend craft guidance — 0.36.0

Executed October 15, 2026, on Windows with Node.js 24.16.0. This is an instructional and packaging change;
no application interface was redesigned as part of this verification.

## Changed behavior contract

- Inspect incumbent visual authority before choosing preservation or replacement. Missing design notes do
  not authorize a rebrand or a documentation prerequisite for a small correction.
- Select composition, critique/repair, visual refinement or shared-foundation work from the actual request.
  These are internal approaches within the existing skill, not new slash commands or menu requirements.
- Commit to a content-specific visual mechanism and carry it through a representative working journey.
  Preserve approved aesthetics, factual content, appropriate familiar components and actual state contracts.
- Load typography/color, motion/feedback, visual-expression and task-scoping references conditionally.
- Use an initial batched inspection and confirmation by default. More review needs a named unresolved
  criterion, new evidence or user feedback. A pass budget cannot conceal functional/accessibility failures.

The guidance was originally written to Proofwork requirements. Comparison informed the capability review;
no external instructional text, implementation, command set or supporting scripts were imported.

The reference guide and skill specification include the added references. Existing composition, component
craft, journey continuity and rendered-review material remains available. The rendered-review and detailed
workflow guides now agree with the entry's conditional scope and bounded finish discipline.

## Evidence limits

Five new prompts in [frontend scenarios](../frontend-scenarios.md) cover narrow refinement, distinctive
publication identity, dark-theme/font fallback, interruptible feedback and findings-only critique. These
are acceptance definitions, not executed browser evidence. No comparative aesthetic, usability, model
quality or application performance gain is claimed. Source/package checks cannot establish those outcomes.
Native host installation and live lifecycle dispatch were not tested for this version. Raw logs stay local.
