# Ten-line function cap verification

Date: 2026-10-10. Version: 0.12.1.

## Delivered policy

Clean-code requires every complete project-owned function definition to fit within ten physical lines. Count attached attributes/decorators, multiline signatures, comments and blanks through the end of the body. Exactly ten passes; eleven fails. Methods, constructors, accessors, local functions, closures/callbacks, tests and generated/existing functions count; nested callbacks count independently and within their enclosing definition.

A new conditional reference explains cohesive extraction, preserved effect/resource contracts, public-signature conflicts and separate complexity assessment below the cap. Compression, exclusion tricks, weakened tests and arbitrary forwarding chains do not satisfy the requirement. Shared engineering principles, coordinator completion guidance, structural review, corresponding specifications, README and reference index carry the policy. Both host packages were rebuilt.

## Limits

No runtime code changed and no automatic function-size checker was added. The bundled file checker measures the 500-line file maximum only. The ten/eleven-line and complexity cases are authored acceptance requirements, not executed language-parser or application evaluations. No repository-wide function audit or refactor was performed; existing runtime functions were not certified against the new limit. Future code work must record language-aware or scoped manual function inspections separately and coordinate unresolved violations outside edit ownership.
