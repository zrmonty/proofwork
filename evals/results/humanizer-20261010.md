# Humanizer verification

Date: 2026-10-10. Package version: 0.5.0.

## Delivered behavior

The original humanizer skill includes two conditional references and an authoring specification. It applies to visible application copy and content structure. It reduces formulaic promises, repeated title layers and unnecessary promotional chrome while preserving useful headings, navigation, required links, supplied facts, accessibility, localization and actual interaction semantics.

Frontend-design explicitly loads it for wording work. The router selects it alongside frontend guidance and for focused interface-copy requests. The README documents Codex and Claude commands. This is an editorial workflow rather than an authorship detector or a guaranteed reader-satisfaction measure.

## Independent forward use and review

The evaluator read the skill and references, then received raw sample copy and product facts without an intended rewrite. It did not edit source or build an application.

For an authenticated reading-group settings screen, it replaced an eyebrow, generic headline, subtitle and repeated preferences introduction with Notifications, a specific reply-email toggle label and Save preferences. Existing global navigation and required Privacy/Support links remained. It removed duplicated promotional navigation and signup copy, while identifying shared-layout consumers as a prerequisite for any actual shared-footer edit.

For a failed event load, it wrote a load-failure message and retained the supported retry rather than an empty-state claim. A queued report remained queued, with output described only at the location established by the supplied behavior. An uncertain payment directed the person to the existing account-status destination instead of encouraging a second payment. The evaluator noted that changing a charge button's label would not change its effect; the actual control must navigate to the stated destination.

For a long public reading guide, it preserved meaningful sections, masthead, archive links and copyright. It did not fabricate body prose that had not been supplied. It retained the invitation key, visible label, member-name interpolation requirement and ICU plural contract; missing exact string details remained unresolved instead of becoming invented replacements. Approved legal consent text remained intact.

No material contradiction was found in the authored skill, references or frontend integration. The reviewer reproduced one routing omission: Rewrite the empty state, Improve button labels and Rewrite notification copy did not select humanizer without a frontend filename or extra UI context word. Regression assertions failed before correction and passed after narrow trigger expansion. Independent follow-up verified all three corrected routes and the HTTP-header exclusion.

## Limits

These checks establish scoped editorial decisions, routing and packaging. No rendered application, keyboard interaction, translated locale or reader study was available. They do not establish visual quality, actual application behavior, universal human preference or detector outcomes. Implemented copy must receive its own context, state and string-contract verification using the target application's facts and tools.
