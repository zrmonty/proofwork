# Dead-code-audit verification — 0.9.0

Adds an originally authored dead-code-audit skill, reachability/test-ownership reference and specification. Root coordination and clean-code guidance load it for explicit cleanup tasks. README commands cover both hosts; both generated packages contain nineteen skills. No dependency scanner or runtime framework was added.

## Contract

The skill establishes supported runtime roots before deleting candidates. It checks dynamic discovery, side-effect imports, external public consumers, supported configurations, generated source and migration retention. Mutually referencing dead modules are evaluated from actual roots. No matches, zero coverage and unused diagnostics alone do not prove deadness.

Proven dead code is removed with dangling imports, exports, registration, configuration and documentation. Tests and artifacts are removed only when their guarantees and consumers belong exclusively to deleted behavior. Mixed tests retain live assertions; shared fixtures, security/compatibility regressions and visible unmet requirements remain protected. Dependency changes use the existing package manager and lockfile convention.

The independent executable-source inventory is updated from surviving code with justified deletions recorded. Separate 95% line/branch floors and stricter gates remain; a higher percentage from a smaller denominator does not establish improved test quality. Live data, public history and external resources are outside source-cleanup authorization.

## Limits

No target-application dead-code deletion, downstream consumer survey, dynamic runtime fixture or fresh host behavioral evaluation was performed for this release. These checks establish routing and package structure. Actual invocation requires target-specific reachability evidence, deletion review, test discovery and surviving-behavior checks; no exhaustive cleanup or performance savings are claimed.
