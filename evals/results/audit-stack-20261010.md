# DRY and combined audit verification — 0.10.0

Adds originally authored dry-audit and audit-stack skills, a conditional duplication reference, specifications, routing, coordinator/clean-code integration and README commands. Both host packages contain twenty-one skills. Existing coordinator, evidence, goal and verification mechanisms are reused; no separate scheduler, scanner dependency or audit framework was added.

## Contracts

DRY auditing distinguishes duplicated knowledge from coincidental syntax. It identifies the invariant, owner and consumers, consolidates a genuinely common pure rule, migrates callers and removes obsolete copies. Separate policy, resource lifecycle, trust-boundary enforcement and unique test guarantees remain protected. A shared validator never removes the server's actual input/authorization checks. Clean no-change findings and retained intentional repetition are valid.

Audit-stack loads security, dead-code, DRY, performance, tests/coverage, architecture and maintainability lenses in one use-proofwork run. Functional/data-driven rules and applicable languages govern repairs. UI/copy and release finishing apply when the surface requires them. Default invocation includes scoped local repairs; explicit report-only instructions remain read-only. External operations and policy/compatibility decisions retain their actual authorization requirements.

Every core lens gets an assessed result, a reason it is not applicable, or an explicit missing capability. Findings of one root cause are merged while distinct evidence obligations remain. Reachability precedes duplication extraction; security/correctness precede optimization. Overlapping modifying auditors are not dispatched concurrently. Final evidence must match the integrated artifact. Missing branch metrics, below-gate coverage, unexecuted profiling and required unresolved findings remain incomplete; instruction loading cannot produce a pass.

## Limits

No target-application DRY consolidation, complete audit-stack execution, browser interaction, production security probe, measured optimization or new coverage collection was performed for this release. Structural validation and routing establish availability only. Real invocation needs per-lens observations, final integrated regression checks and explicit dispositions for gaps; no comprehensive correctness, security or performance certification is claimed.
