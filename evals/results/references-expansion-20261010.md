# All-skill reference expansion — 0.11.0

All twenty-one skills gained one originally authored, conditionally loaded reference: twenty-one additions, bringing the canonical collection from thirty-four to fifty-five references. Each entry states when to read the new material, and each matching specification maps its decisions and acceptance cases. The [reference guide](../../docs/reference-guide.md) links the complete collection. Entry points remain focused; this does not make every reference mandatory reading.

Three bounded author groups read the owned entries, existing references and specifications before writing. No external skill assets were copied, adapted or mechanically paraphrased. The authoring standard now covers all twenty-one skills and rejects orphan references, competing policy and added length as a quality metric.

## Independent review

A fresh read-only reviewer read all twenty-one new references with affected entry/specification context. Verdict: **meets the bar; no material findings**. The reviewer found distinct practical decisions and no competing schemas, verdicts, infrastructure requirements or quotas.

The review confirmed retention of pure state/data decisions with explicit effect owners, strict Python consumer/test checks, independent executable inventory, separate 95% line/branch floors, stronger existing gates, the hard 500-line code maximum and secret redaction before output. Public/durable consumers, historical precision and authoritative boundary enforcement remain protected. Visual and navigation claims require actual rendered/interaction evidence.

The reviewer separately reasoned through three supplied hypothetical fact sets without an intended answer:

- An old job handler remains necessary while accepted jobs are supported for thirty days; an obsolete producer or truly private formatter can be evaluated separately. Identical estimate arithmetic does not authorize recomputing historical signed-invoice values.
- Warm-cache speed does not establish permission or freshness. Access revocation and export polling need their actual lifecycle/policy traced. A changed report-only instruction controls further work, and unavailable branch metrics leave that gate unverified despite 100% lines.
- An attractive publication index cannot close clipped detail headlines or lost return filters. Screenshot evidence cannot establish history/focus behavior, and reference mechanisms should inform the product's own composition.

These are hypothetical reasoning observations, not executed application scenarios or evidence of improved agent performance.

## Limits

This release adds decision guidance and structural verification. No target-application implementation, live access lifecycle, actual release, fresh host invocation, cache benchmark, coverage collection, downstream build matrix or browser journey was executed for these additions. The source verdict and selected hypothetical reasoning do not certify all skill behavior, comparative quality gains, production security or visual results. The references retain those checks as obligations when used on a real project.
